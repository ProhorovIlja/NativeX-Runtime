## Precise upstream engineering leads from public code (not copied)

- **[Xbox2Windows PR #394](https://github.com/R0Y00/Xbox2Windows/pull/394) (MIT):** author-reported native CRT-free EXE lifetime regression verifies `ExitProcess` at native process startup return, while mapped PE execution returns control to its host. It also tests worker-thread lifetime and two pipe EOFs. **Our PE fixture exit codes 42–47 do not validate all this behavior.** Future original regression should distinguish normal desktop process exit, loader-resident entry return and active worker/thread shutdown.
- **[Xbox2Windows PR #413](https://github.com/R0Y00/Xbox2Windows/pull/413) (MIT):** a conditional `Jcc` whose explicit target equals its next instruction was accepted by an AOT translator without emitting a label, giving a C++ compile failure. The author claims 1,840 randomized differential CPU functions subsequently passed. Our user's target permits **native x64 CPU execution**; do not force AOT rewriting unless technically justified, but retain this as an independent negative test for any optional static recompiler.
- **[Xbox2Windows PR #410](https://github.com/R0Y00/Xbox2Windows/pull/410) (MIT):** a failed pixel-shader disassembly should be marked as a **blocking PSO failure**, not `needs_evidence` with null reason. Use this failure-state distinction when building our own GPU pipeline readiness tooling; no real GTA VI PSO inventory is available.
- **[DirectXTex PR #763](https://github.com/microsoft/DirectXTex/pull/763) (MIT):** upstream found a green-bit shift that contaminated the red channel in RGB565 DDS conversion (November 21, 2026). Our synthetic BC1/BC3 CPU and GPU tests independently assert exact RGB565 red/green/blue channel values and interpolation; this is a useful example of why a separate pixel oracle matters, not evidence we imported a DirectXTex fix.
- **[Microsoft GameInput PR #63](https://github.com/microsoftconnect/GameInput/pull/63) (MIT):** official sample helper includes discrete DualSense adaptive-trigger effects and reports its protocol limits. Valid output packets were **not** issued to real USB/Bluetooth controllers in this repository. Physical-device safety and feature acceptance must be separate, opt-in on supported hardware.
- **[XCL](https://github.com/ivall/xcl) GPL-2.0** and **[AnyXboxX](https://github.com/LooperSalty/AnyXboxX) GPL-3.0**: source may be studied and built **outside** this project's MIT distribution, but copying implementation requires satisfying separate GPL obligations. [TomBox](https://github.com/drycheetah84/TomBox) had no recognizable repository license at the inspected revision; keep it as a research lead until permission is clear. Do not infer game support from any self-reported decoder opcode percentages or black-screen title runs.

## Implementation priority, with acceptance gates

1. **Windows title native first:** lawfully inspect actual Xbox Series X PE32+ imports by DLL and symbol/ordinal, exact Microsoft GDK ABI, section/TLS/unwind handling and title resource formats; carry real native x86-64 code using a measured, correctly licensed host adaptation without CPU instruction emulation where technically feasible.
2. **GPU title correctness:** map console-style D3D12.X semantics, RDNA2 wave/subgroup instructions, root signatures/descriptors, BC7 and swizzled texture data, shader pipeline readiness and actual game raster output. Validate GPU/CPU pixel oracles on physical AMD/NVIDIA/Intel hardware, **not just WARP**.
3. **Game-system correctness:** content-aware asset streaming and true DirectStorage/io_uring capability checks, stable synchronized audio/video, continuous full-world simulation, Windows Raw Input/GameInput device ownership, safe save/journal recovery and repeatable p50/p95/p99 frame/input timing. Provider APIs (DLSS/FSR/XeSS, DLSS5, Reflex) are **optional** and require actual scene guides, OS/GPU/driver/SDK license support.
4. **Linux native ELF/Vulkan second** (Proton is an optional Windows-PE compatibility route, not an ELF port), then **co-op and user-requested mission/relationship features only after full Windows single-player campaign stability**.

No proprietary game files were sought, no unlicensed source copied, no scheduled tasks, automation or ongoing background checks created.
