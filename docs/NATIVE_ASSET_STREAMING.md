# Portable native Windows and Linux asset streaming baseline

This is a real, source-built asynchronous **worker-thread + filesystem** implementation in C++17, not merely a planned API. It reads deterministic synthetic local files on Windows and Linux with asynchronous futures, fixed-size request limits, cancellation, offset/EOF validation, FNV-1a integrity checks and clean queue draining on shutdown.

Files:
- src/native_asset_stream.hpp and src/native_asset_stream.cpp define bounded requests, status/error results and a native worker pool.
- fixtures/native_asset_stream_tests.cpp creates 2 MiB of its **own synthetic bytes**, checks 64 independent read offsets/content/checksums and rejected invalid/missing/cancelled requests. The test also checks futures remain completed after an owning reader drains pending work during destruction.

**Security:** no game assets, title-specific compression, RPF data, GPU file writes, shaders, leaked keys or external binaries. Offset+length overflow is rejected via subtraction after checking the offset; individual reads are capped to 4 MiB. The host OS filesystem and C++ standard threading primitives do the work.

**Performance boundary:** this is the portable fallback, not Windows DirectStorage, GPU decompression, NVMe GPU-to-memory transfer or Linux io_uring. No DirectStorage/io_uring API is called and no throughput claims are made. Those would be separate backend implementations behind the same validation and cancellation contract, requiring measured I/O workloads and legal input format knowledge.

Future tests: cancellation mid-stream, race/no-use-after-free, buffer residency, back-pressure under saturated queues, truncated file while active, checksum plus format-specific legal samples, Windows IOCP/DirectStorage vs Linux io_uring with verified kernel, and p95/p99 streaming stalls on target hardware. Keep a portable fallback for unsupported or remote drives.

FNV-1a is used as a fast, deterministic corruption-detection fixture checksum, **not a cryptographic content-authentication hash**. Production asset integrity will require authenticated manifests or a strong cryptographic hash where untrusted data enters the pipeline. The worker constructor also joins already started threads if another thread creation fails, preventing std::terminate on partial startup. Both Linux and Windows builds passed.

## Outstanding read admission budget (2026-11-24)

Reader now accepts a third constructor argument, requested-byte budget (default 128 MiB). Admission counts both queued and executing requests. Insufficient available credit returns Status::BudgetExceeded; callers must handle backpressure. Previously completed buffers retained by callers are not included. Credit is returned before the future is ready even on exceptions. Pre-cancelled valid requests return Cancelled before admission, with a further cancellation check after hashing. Reader::stats() provides a synchronized snapshot of queued/active requests, outstanding bytes, peak outstanding bytes and budget. Existing queue count and weighted fairness remain. Global budget is not a priority reservation or a cap on total RAM/VRAM. The standalone regression fixture uses 512 attempts and a 128 KiB test budget; the measured peak never exceeded the cap. This is not a measured application or SSD speedup.

## Critical admission reserve (2026-11-24)

An optional fourth Reader constructor argument, AdmissionReserve {bytes, queued_slots}, protects critical admission against Normal/Background requests. Defaults are zero for compatibility. Noncritical outstanding requested bytes are bounded by global budget minus reserved bytes, and noncritical queued count by queue limit minus reserved slots. FrameCritical may consume available global capacity. Full reservations intentionally exclude the corresponding noncritical capacity (zero-byte reads can still pass a full byte reservation). Invalid values are rejected. The byte credit covers queued and active requests, not completed buffers. Queue reservation is not a reserved worker or deadline guarantee. Backpressure uses existing BudgetExceeded/QueueFull statuses; weighted dispatch fairness remains unchanged. Stats expose current noncritical counts and reservation. Independent 1536-attempt mixed-priority regression passed strict GCC and Clang and GCC ASan/UBSan with 256 KiB global budget, 128 KiB reserved and two reserved slots. No measured game performance, Windows backend or GPU claim.

## Completed asset cache (2026-11-24)

Optional AssetCache uses bounded LRU with payload-byte and entry limits, explicit case-sensitive asset identity, generation, offset and length keys, immutable shared results, duplicate/conflict detection and checksum validation. Callers look up before submitting a Reader request and publish successful results explicitly. Callers must change the generation when content changes and coordinate invalidation with in-flight publishers if a barrier is required. Cache-owned payload is bounded, not temporary copies, allocator overhead or external shared ownership. No automatic file monitoring or concurrent miss coalescing. Original test performs 1024 logical reads of 16 blocks with 16 Reader submissions, then 4096 concurrent cache operations. This is a synthetic reuse count, not an SSD or game speedup.

## Coalesced immutable asset reads (2026-11-24)

Optional CoalescedReader combines bounded same-key, same-priority in-flight reads with AssetCache. It blocks callers and creates no additional workers. Different priorities do not join, avoiding implicit priority demotion. Individual cancellation is checked before admission and before/after waiting, not interruptibly during waiting; shared work is not cancelled by individual subscribers. Failed reads are not cached; exceptions retire the flight and propagate to uncancelled callers. AssetCache::publish returns the exact immutable shared buffer (including uncached oversized valid results). The existing insert interface remains. Caller-supplied immutable identity/generation and path correspondence are contractual; no automatic file monitoring or invalidation barrier. Active distinct flights are bounded, but waiting threads and externally retained buffers are not globally bounded. Synthetic controlled group: 16 callers, one backend invocation, 15 joins. Portable Reader test: 1024 calls to two blocks, two actual Reader submissions. These are call counts, not physical disk operations or measured game speedup. No automatic jobs.

## Lifetime-aware published payload budget (2026-11-24)

AssetCache and CoalescedReader accept an optional live_limit (zero unlimited), separate from resident and outstanding-read budgets. Published payload remains charged while any consumer owns its immutable shared pointer, including after eviction, clear, invalidation or uncached oversized publication. Credit returns after final release; tracking state outlives cache destruction. Cache-only entries may be reclaimed under pressure even if admission ultimately fails. Admission checks the actual outstanding counter; shared ownership cannot bypass the cap. Publication rejection returns LiveBudgetExceeded and CoalescedReader returns BudgetExceeded. The configured limit must be at least the resident budget. This per-cache payload limit excludes untracked allocations, temporary results before publication, outstanding reads, allocator overhead and VRAM. No Windows or game performance claims.

## Pre-I/O payload commitment (2026-11-24)

Move-only AssetCache::Reservation tickets charge requested bytes before backend reading. publish_reserved transfers credit to a tracked shared payload without double charging, and rejects foreign or mismatched tickets. RAII returns unused credit on failure, duplicate, conflict or exception. The synchronized live state exposes reserved_bytes, committed_bytes and peak_committed_bytes; the configured live_limit now bounds live plus reserved bytes. Cache-only entries may be evicted to reserve credit; zero limit remains unlimited. CoalescedReader reserves before invoking backend, and reports BudgetExceeded without I/O on denial. leader_reads counts actual backend invocations; rejected includes budget denial. Direct publish remains supported, but caller-side pre-publication allocation is not covered unless explicitly reserved. Accounting covers requested/published payload only, not entire process RAM, decoder scratch, excess allocation capacity or VRAM. Separate priority flights and immutable identity/generation contract remain. No automatic monitoring or jobs.

## Optional bounded Zstandard decoder (2026-11-24)

Original native_asset_decode component uses installed libzstd (1.4.0+, tested 1.5.7), upstream BSD OR GPLv2. No vendored library, no automatic download. Enable manually with -DNATIVEX_ENABLE_ZSTD=ON (default OFF). Accepts a single standard frame with independently supplied exact expected length, default 16 MiB output limit, hard 64 MiB output cap, Reader's 4 MiB compressed-input cap, default maximum streaming window log 23. Rejects nonzero dictionary IDs, skippable/concatenated/trailing frames, malformed input, incorrect size/checksum, and partial output. Cancellation checked between bounded output slices, not inside a library call. This is a synchronous, per-call decoder; parallel output totals, scratch memory, input buffers and other process memory are outside its limit. Original fixture verified read/cache/decode integration and 128 parallel round trips per run. No claim of actual game codec support. References: https://facebook.github.io/zstd/doc/api_manual_latest.html and https://github.com/meta/zstd.

## Shared decode budget and CPU pixel integration (2026-11-24)

Optional BudgetedDecoder wraps zstd_frame, reserves expected output payload before decoding and limits simultaneous decode calls. A shared immutable Decoded result retains its RAII credit until the last owner releases it; state survives decoder destruction. Errors, cancellation and exceptions return credit. OutputBudgetExceeded also indicates concurrent-call admission denial. The budget excludes compressed input, codec scratch, allocator overhead, consumer copies and VRAM. Synchronous caller-side interface; no new worker or background service. Source-generated fixture reads two independent Zstd records through Reader/CoalescedReader, assembles RGBA8 pages on CPU and checks all 16384 pixels. Two successful backend reads plus separate EOF negative control. Inspired by public Xbox2Windows PR #1331 test methodology; no code imported. This is not BCn validation or GPU rendering. Full Windows/CMake tests remain unverified.

## Portable texture upload staging (2026-11-24)

Original native_texture_upload planner and packer handle single-plane 2D RGBA8 and BC1/3/4/5/7 storage geometry, mip chains and array layers. D3D12-style row pitch and subresource placement alignments are 256 and 512 bytes respectively. The conservative allocation includes full final rows and zeroed padding, and rejects invalid or truncated views before copying payload. The actual device GetCopyableFootprints remains authoritative. This is CPU staging only, not a full GPU resource validator, upload or render. BC blocks are copied, not decoded. Per-call staging cap is 256 MiB; external buffers, total RAM and VRAM are excluded. The integrated independent Zstd fixture checks staging of two RGBA8 array layers against 16384 CPU pixels and rejects a truncated second layer. References: https://learn.microsoft.com/en-us/windows/win32/direct3d12/upload-and-readback-of-texture-data and https://learn.microsoft.com/en-us/windows/win32/api/d3d12/nf-d3d12-id3d12device-getcopyablefootprints. No upstream code incorporated.

## Fence-governed upload memory (2026-11-24)

Original UploadArena suballocates aligned ranges of externally owned upload memory using first-fit gaps. Single owner thread and single monotonic GPU fence timeline only. Capacity at most 256 MiB and 4096 live allocations. Reserve, cancel before GPU use, seal before submission, and collect only observed completed fence values. Sealed slices cannot be cancelled, stale tokens within the same arena are rejected, and UINT64_MAX (device-loss sentinel) does not release ranges. Tokens are instance-scoped. External caller owns backing memory, queue submission, actual fences and device-loss recovery. No GPU calls, implicit waits, cross-queue synchronization or automatic retirement. Linear scan and fragmentation remain possible. Reference: https://learn.microsoft.com/en-us/windows/win32/direct3d12/fence-based-resource-management .

## Windows texture upload roundtrip fixture (2026-11-24)

Original Windows-only source for two RGBA8 textures with three mips and two array layers each. Compares CPU staging geometry with GetCopyableFootprints; records upload and readback copies, seals two arena allocations and reuses the first only after observing its fence. Checks twelve subresources against independent original bytes. WARP test registered for manual CTest execution; explicit nvidia argument chooses the first compatible NVIDIA adapter without software fallback. Exit 77 means unavailable. Uncertain GPU completion terminates the standalone test process, not a production recovery path. Local GCC/Clang portable regressions passed; new Windows source has not been compiled or run. No real GPU result, game data or performance claim. References: https://learn.microsoft.com/en-us/windows/win32/api/d3d12/nf-d3d12-id3d12device-getcopyablefootprints and https://learn.microsoft.com/en-us/windows/win32/direct3d12/upload-and-readback-of-texture-data .

## Persistent pipeline blob cache (2026-11-24)

Original portable native_pipeline_cache stores opaque locally generated driver blobs under exact byte keys and an explicit compatibility scope. Caller must canonicalize complete pipeline state and supply adapter, driver, runtime and compiler/translator identities. Configurable maximum serialized snapshot 64 MiB, 4096 entries, 1 MiB key, 16 MiB blob, 4096-byte scope. Full insertion/replacement is rejected without changing the map; explicit erase. Versioned little-endian snapshot, whole-file FNV-1a checksum (accidental corruption only), strict structural validation, duplicate rejection and transactional load. Save stages in an exclusively created directory beside the destination and renames; trusted local directory and single owner only, no concurrent writer or crash-durability guarantees. Snapshot cap is not total RAM. No auto-save, worker or scheduling. Actual D3D12 cached PSO creation/rejection fallback and Windows persistence remain untested. See https://learn.microsoft.com/en-us/windows/win32/api/d3d12/ns-d3d12-d3d12_cached_pipeline_state and https://learn.microsoft.com/en-us/windows/win32/api/d3d12/nf-d3d12-id3d12device1-createpipelinelibrary .

## Cached compute pipeline creation (2026-11-24)

Original native_pipeline_build creates a versioned canonical exact-byte key for legacy D3D12 compute PSO descriptors from the serialized root signature, shader bytes, flags and node mask. Cache scope is separate. Callback-based creation attempts a cached blob first; explicit cache rejection erases it and triggers one uncached retry. Unrelated failures are not retried or evicted. Cold/rebuilt success may store a new blob; ordinary cache capacity denial does not negate creation. Exceptions propagate. Caller owns the native pipeline object; single owner, no callback reentrancy or cache mutation. Windows-only source-built compute fixture calls CreateComputePipelineState and GetCachedBlob, saves/reopens a same-run temporary snapshot, dispatches cold and warm pipelines and compares 128 values to a CPU oracle. WARP or explicit NVIDIA adapter; skip if reusable blob unavailable. Windows source uncompiled/unexecuted locally, no timing or GPU pass claimed. Scope valid only for that fixture's same device and same run; no cross-run identity detection yet. References: https://learn.microsoft.com/en-us/windows/win32/api/d3d12/ns-d3d12-d3d12_cached_pipeline_state and https://learn.microsoft.com/en-us/windows/win32/api/d3d12/nf-d3d12-id3d12pipelinestate-getcachedblob .
