# Native Windows/Linux PCM reference audio and WASAPI host probe

The original portable C++17 `src/native_audio_mix.{hpp,cpp}` provides a deterministic, allocation-free **stereo float** reference mixer for up to 64 independent voices and 4096 frames per call. It validates all source pointers, frame lengths and finite gain ranges before changing outputs; non-finite input samples are sanitized, a double-precision internal sum is clipped to [-1,+1], and clipped/sanitized counts plus peak are reported. Original Linux/Windows CTest fixtures cover stereo channels, gain, hard clipping, non-finite samples, invalid control rejection, silence and maximum supported dimensions. These are correctness reference tests, **not** optimized final middleware.

A separate native Windows x64 `fixtures/native_win_wasapi_probe.cpp` calls real Windows Core Audio COM methods `IMMDeviceEnumerator::GetDefaultAudioEndpoint(eRender,eConsole)`, `IMMDevice::Activate(IAudioClient)`, `IAudioClient::GetMixFormat` and `GetDevicePeriod`. It verifies that an attached audio endpoint returns a structurally usable shared-mode mix format and reports native sample rate, channels, bit depth and device periods. Headless CI agents may have **no audio endpoint**: this case explicitly returns CTest skip code 77, so compilation is verified but hardware and playback are **not** misrepresented. No microphone recording, audio output or background service is started.

## Candidate production architecture (not implemented yet)

- Windows desktop: investigate event-driven WASAPI shared mode (`IAudioClient3` small period when supported) versus XAudio2 audio-graph handling, with dynamic endpoint changes, communications/music mixing, sound effects and spatial audio; measure latency, dropouts, power cost and CPU budget before committing.
- Native Linux: review PipeWire/SDL3 support and audio backend fallback on supported distributions; the portable reference mixer compiles to native ELF, and Proton remains a separate compatibility route.
- Audio asset codecs/voice system: cannot be chosen until a lawfully available build reveals the actual game containers, spatial mixing, sample formats and content. Do not copy proprietary game audio middleware or assume Windows Sonic/Dolby license or hardware support.
- Quantitative acceptance: real endpoint streaming, callback jitter, dropout recovery, resume/hotplug and device changes, output/capture privacy, 44.1/48/96 kHz testing, p95/p99 latency, and CPU/allocations profiling on target hardware.

Official reference sources: [Microsoft WASAPI IAudioClient](https://learn.microsoft.com/en-us/windows/win32/api/audioclient/nn-audioclient-iaudioclient), [GetMixFormat](https://learn.microsoft.com/en-us/windows/win32/api/audioclient/nf-audioclient-iaudioclient-getmixformat), [default endpoint selection](https://learn.microsoft.com/en-us/windows/win32/api/mmdeviceapi/nf-mmdeviceapi-immdeviceenumerator-getdefaultaudioendpoint), and [low-latency IAudioClient3 device periods](https://learn.microsoft.com/en-us/windows/win32/coreaudio/exclusive-mode-streams). No external binary dependencies, game files or paid runners.
