# Native Windows/Linux integration — sixth verified pass (2026-11-22)

This records **independent, publicly source-built tests** made for the user-provided `Порт GTA 6.md` Windows-first project. The actual Xbox Series X GTA VI EXE, engine scripts, resource archives, shaders and game saves are **not available** in this repository. Windows x64 single-player campaign compatibility is the main goal; native Linux ELF/Vulkan is secondary, Proton optional, and co-op/features deferred until real Windows gameplay works.

## Engineering implications and integration hierarchy

- **GDK / ABI and exceptions first:** before claiming a native Xbox executable works, inspect its legally sourced PE32+ imports, TLS, .pdata and .xdata; map **actual** GDK interfaces to host APIs. The accepted V1 analysis only inventories part of UNWIND_INFO. The true Windows OS unwind tests do not prove a foreign manual PE loader has registered every game function table.
- **Native CPU execution where feasible:** x64 instructions can be executed natively, but console services, address layouts, GPU barriers and game APIs are **not** magically identical to Windows desktop interfaces. Do not use a blanket 'no emulation' marketing claim to hide required adapters, or silently adopt software GPU results as hardware evidence.
- **Rendering:** continue with concrete D3D12/Xbox RDNA2 resources, shader pipelines and true game materials when available; the [real original BC1/BC3 D3D12 WARP GPU tests](NATIVE_WIN_D3D12_BC_GPU_CPU_2026-11-22.md) are a host API gate, not a Rockstar frame. Compare physical AMD/NVIDIA/Intel hardware, D3D12/Vulkan resources, BC7 tiling and WSI.
- **Modern PC features:** official NVIDIA Streamline/DLSS, AMD FSR SDK, Intel XeSS, DirectStorage, GameInput 4.x and DirectXTex are **provider candidates**, not automatic FPS or quality upgrades. Verify exact native GPU/driver/SDK license requirements and how real scene motion/depth/HDR/jitter data is exposed. Neural rendering labelled DLSS 5 requires its own officially supported integration; do not bundle unknown binaries.
- **Controller acceptance:** native Raw Input for KBM remains preferred; use GameInput/XInput/device-specific HID only for genuinely supported devices. The new radial processing is an engine-side pure function, **not** Sony hardware adaptive-trigger support. Physical USB/Bluetooth and latency acceptance remain separate tests.
- **Save safety:** the fail-closed regression is not a replacement for real game serialization, task-safe autosave, disk-full/power-cut tests, atomic world progression and actual campaign save-reload acceptance.
