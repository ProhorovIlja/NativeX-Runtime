## Fresh upstream code research, with claims kept separate

**XCL** — [commit `660f6dc2f0ee`](https://github.com/ivall/xcl/commit/660f6dc2f0eec8a14cf69c7cae0d8f1813da1fa1) (2026-11-22) introduces author-described sparse GPU UMA windows, each 4 GiB backed by mapped 64 KiB tiles, 64-byte changed-region synchronization, console root arguments, vertex-buffer address translation and graphics command fixes. Author reports *XDefiant can run about 90 s without GPU hang but still renders black frames*. That is **not our reproduced result**, and a black frame is not a playable game. XCL's GPL-licensed implementation has not been copied. Our own tile fixture #53 only validates the host D3D12 primitive.

**Xbox2Windows** — [PR #362](https://github.com/R0Y00/Xbox2Windows/pull/362) describes source-level acceptance of gfx10 scheduling hints (`s_clause`, `s_setprio`, `s_sleep`) plus validator and hardware differential checks, with author-reported Radeon RX 9070 XT/WARP results. [PR #372](https://github.com/R0Y00/Xbox2Windows/pull/372) adds original CPU jump-table mutation fixtures; [PR #378](https://github.com/R0Y00/Xbox2Windows/pull/378) adds an author-supplied RX 5600 XT wave32/64 hardware report. These are actionable **test designs to study**, not a validated GTA VI RDNA2 conversion, nor imported into our code.

**AnyXboxX** — latest inspected [merged PR #77](https://github.com/LooperSalty/AnyXboxX/pull/77) improves AMD gfx10/RDNA2 operand disassembly against LLVM examples. Main license changed to **GPL-3.0-or-later** from earlier LGPL. Our independently source-built external runtime passes five Win32 desktop PE fixtures, but has not executed actual console GPU shaders or the official Microsoft GDK sample.

**Official GDK sample** — Microsoft [SimpleTriangleDesktop](https://github.com/microsoft/Xbox-GDK-Samples/tree/b1e77b6ac10f95b07296025fda171ca2ddc42dbe/Samples/IntroGraphics/SimpleTriangleDesktop) is public, but its project uses `GameDKCoreLatest`/GDK include and library paths, and source `pch.h` requires `grdk.h`, Xbox runtime headers, DirectXTK12/ATG support and a GDK edition at least October 2025. Its README still mentions March 2022 compatibility, while the current actual compile guard demands a newer GDK. **We have not compiled the unmodified official sample on stock public Windows CI.** Our original DXGI fixtures instead provide clean source-built evidence without closed or separately installed GDK dependencies.

## Technology selection policy

- **Use components based on measured behavior and integration costs, not GitHub stars or one language.** C++17/20 for Windows ABI/D3D12/GameInput and cross-platform hot paths; use Rust for isolated parsers, IPC, file/network components only where ownership and benchmarking make it advantageous. A language rewrite alone is not a speedup.
- **Windows primary:** native x64, D3D12/DXGI, optional Vulkan where independently validated, correct file memory semantics, system GameInput/Raw Input and WASAPI; DirectStorage only after asset format and Windows SDK capability verification. Current IOCP is not DirectStorage.
- **Linux native second:** independent ELF build/Vulkan/PipeWire/SDL3, optional io_uring after hardware/storage measurement. Proton may run Windows binaries as an alternative but is not a native Linux ELF port.
- **Graphics options:** FSR, DLSS, XeSS, Reflex and other vendor APIs are gated by API/backend, SDK license, physical driver/GPU capability and scene motion/depth data. DLSS 5 neuro-rendering and experimental GitHub injectors are **not** presumed safe, licensed, supported or executable from current sources.
- **Sound/video/storage/network:** required production work is real audio playback/hotplug and video decoding, content-aware streaming, filesystem/SSD stress tests, memory budget/residency and socket latency; not all subsystems should be replaced merely for novelty.

## Next real acceptance milestones

1. Obtain a **lawfully available** Xbox Series X game build: inspect true PE imports/ABI/serialization, title-specific memory, GDK services, command lists, asset files and shaders. Do not guess APIs or invent title compatibility without it.
2. Integrate actual Xbox D3D12.X and RDNA2 translated instructions on native Win32 with CPU reference, differential pixel checks and hardware AMD/NVIDIA/Intel GPU validation. Get real frames and a stable single-player boot.
3. Real data/scene optimization: CPU/VRAM/IO, shader caches, loading, graphics settings, quality options, actual p50/p95/p99 frame times, input-to-present latency, audio dropouts and crash-free sessions. Confirm saves and all chapters of the story are playable.
4. Native Linux renderer/OS services after Windows functionality is established; separate actual ELF tests from Proton comparisons.
5. **Only then** implement networking, cooperative missions and optional mission skipping/relationship mechanics, preserving save integrity and correct story progression.

This batch did not source leaks, copy proprietary game material, merge incompatible GPL into MIT, or create any new scheduled tasks or background monitoring.
