# Real Windows native PE TLS callback lifecycle and independent per-thread data

Original Windows x64 host-loader acceptance (2026-11-22): `fixtures/native_win_tls_module.cpp` is compiled into an independently source-built **regular Windows DLL** with a PE TLS callback pointer explicitly emitted in the standard `.CRT$XLB` section. `fixtures/native_win_tls_loader.cpp` is a separate source-built EXE that opens the **exact DLL path supplied by CMake**, dynamically resolves four original exports and tests genuine Windows loader behavior.

The DLL exposes a static `__declspec(thread) int` with initial value **17**. The PE TLS callback records `DLL_PROCESS_ATTACH`, `DLL_THREAD_ATTACH` and `DLL_PROCESS_DETACH`; the DLL `DllMain` records corresponding process/thread lifecycle messages. On process attach, DllMain **rejects loading** if the TLS callback was not invoked first. On worker thread attach, the DLL checks callback-before-DllMain ordering. On process detach, both callback and DllMain increment separate host-owned counters.

The EXE loads the DLL through `LoadLibraryExA` with restricted search flags, checks process callback / DllMain counts and initial thread value 17, changes the main thread's copy to **31**, starts **one real CreateThread worker** and verifies its independent TLS variable starts at **17**, changes only in that worker to **77**, then verifies the main thread still reads 31. It checks both thread-attach callback paths and the callback order, calls FreeLibrary and checks both process-detach notifications were delivered. An unexpected callback order, missing export, incorrect thread state, failure to detach or worker timeout is a CI failure.

This complements the [read-only PE32+ TLS callback VA inventory](PE32_TLS_CALLBACKS_2026-11-22.md): the parser inspects metadata from a synthetic PE without executing code; this test actually exercises **normal Windows loader** `LoadLibraryEx` and CRT/TLS initialization. Their combination **does not** mean an arbitrary manually mapped Xbox PE calls TLS callbacks, supports dynamically loaded Game Core DLLs or follows the Xbox GDK ABI. The [native registered-unwind test](NATIVE_WIN_DYNAMIC_SEH_UNWIND_2026-11-22.md) is a separate verified exception handling gate, not a TLS test.

No commercial game files, unlicensed source, external service, driver, CPU emulator or scheduled task. Source contract: [Microsoft PE TLS section](https://learn.microsoft.com/en-us/windows/win32/debug/pe-format#the-tls-section) and [TLS callbacks, DLL entry points](https://learn.microsoft.com/en-us/windows/win32/dlls/dynamic-link-library-entry-point-function).
