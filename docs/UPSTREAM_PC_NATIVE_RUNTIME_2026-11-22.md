# Native Windows/Linux PC research — graphics, frame queue, input and upstream audit

Date: 2026-11-22. This report records *verified outputs of source-built original fixtures* separately from the authors' claims in public GitHub projects. The attached project `Порт GTA 6.md` sets the order: native Windows x64 single-player execution and stability first, native Linux ELF second; network co-op and mission/relationship additions only after a working game. No GTA VI game binary, commercial assets, real console D3D12.X packets or compiled Rockstar shader instruction traces were obtained.

## Verified upstream repository changes — do not confuse test metrics with gameplay

1. **Microsoft DirectStorage** — [PR #178](https://github.com/microsoft/DirectStorage/pull/178), merged 2026-11-19, expands a zstdgpu `executeIndirectWorkaround` path, whose author describes correctness/performance improvements and avoidance of GPU driver bugs on tested hardware. A DirectStorage **repository change is not evidence** that its runtime is integrated here, that a GTA asset container uses Zstd, or that NVIDIA/AMD/Intel graphics decompression works on our systems. Before integration: identify real payload formats, official SDK binaries/redistribution terms, target NVMe, GPU capability and version-specific behavior; benchmark against the independently proven Win32 IOCP fallback.
2. **AnyXboxX** — [PR #78](https://github.com/LooperSalty/AnyXboxX/pull/78), merged 2026-11-22, reports author-generated coverage graphs: CPU 100%, GPU 521/1458 (36%), system 876/1337 (66%), GDK 152/396 (38%), and an external `d3d12_xs.dll` count of 1/1 explicitly **untested with a game**. The CPU '100%' is a **project accounting convention**, not a claim that any retail Xbox Series game is bootable. Earlier [PR #77](https://github.com/LooperSalty/AnyXboxX/pull/77) improves RDNA2 operand disassembly. The latest source carries **GPL-3.0-or-later** terms; no code was copied into this MIT repository.
3. **TomBox** — [PR #6](https://github.com/drycheetah84/TomBox/pull/6), merged 2026-11-21, describes RPF9 scanning, PSO-aware descriptor/resource translation and shader testing; author reports **122/320 shaders compiling** versus earlier 93/320, but also explicitly says rendering correctness was not verified. Listed limits include unbounded mesh exports, unknown initialization bits, wave64/wave32 gaps, unreliable register spaces and offline-only PSO binding; no GTA VI asset-format compatibility may be inferred from the filename RPF9 alone.
4. **XCL** — [commit `660f6dc2`](https://github.com/ivall/xcl/commit/660f6dc2f0eec8a14cf69c7cae0d8f1813da1fa1) describes mapping guest 64 KiB sparse UMA pages into host reserved D3D12 buffers, GPU root-argument and vertex-buffer translation. The author reports XDefiant running 90 seconds without a driver hang while still displaying black frames. Our own WARP tile-mapping fixture independently validates only basic host tile semantics; we did **not** reproduce their guest-address mapping or copy GPL code.
5. **Xbox2Windows** — [PR #362](https://github.com/R0Y00/Xbox2Windows/pull/362) adds gfx10 scheduling hint acceptance and author-tested hardware/WARP translation checks; [PR #372](https://github.com/R0Y00/Xbox2Windows/pull/372) adds mutation-based CPU jump-table test cases. Tests are useful methodological inputs but do not imply GTA VI rendering or correctness on an untested GPU.
6. **First-party PC upscaling and controller sources** — [AMD FidelityFX SDK](https://github.com/GPUOpen-LibrariesAndSDKs/FidelityFX-SDK) at its 2026-10-28 FSR SDK 2.4.0 revision, [NVIDIA Streamline](https://github.com/NVIDIA-RTX/Streamline) at its 2026-10-16 2.14.16 revision, and [Microsoft GameInput](https://github.com/microsoftconnect/GameInput) at its 2026-11-17 4.1/API DualSense helper update have public reference code. These revisions are **SDK/source metadata**, not working integrated DLSS/FSR/XeSS/Reflex, neural DLSS 5 mod support, DualSense Bluetooth adaptive triggers or physical hardware validation. Official driver and SDK license/redistribution boundaries remain.

## Technology decision: adapt, do not blindly merge

A cross-project merger should first pass: compatible licenses and redistribution rules; real target platform ABI; source build from pinned commit; independent CPU/GPU pixel/data oracle; device capability gating; bounded memory and failure handling; quantitative p50/p95/p99 measurement on chosen hardware; and no regression in the documented upstream and own fixtures.

**Windows** remains the first production target for native x64/Win32/D3D12/DXGI and hardware-specific upscalers. **Linux** must eventually be a native ELF Vulkan implementation with its own input/audio/storage path; Proton/vkd3d-proton is a useful optional *Windows software on Linux* route but not a substitute for a native ELF port. Replacing C++ hot paths with Rust should be driven by safety/ownership boundaries and benchmarks, not the assumption that one language is always lighter or faster.

### Next falsifiable blockers

- Verify a lawfully obtained, real Xbox Series X build's PE format, OS/GDK imports, GPU binary ISA, memory allocation and asset container structure; derive the first actual Xbox-specific differential fixture and title boot acceptance test from evidence, never guess it from open-source README percentages.
- Complete native Windows renderer and full game execution, then cross-check shader output and frame pacing on **physical AMD/NVIDIA/Intel GPU hardware**; add real input-to-Present and display instrumentation and official upscalers only when scene motion/depth/driver data is available.
- Native Linux Vulkan WSI/display Present and real hardware raster before promising a playable ELF title, while keeping the original portable Vulkan raster oracle as a first regression test.
- Hardware acceptance for dual USB/Bluetooth controllers, adaptive triggers/haptics and WASAPI playback/hotplug; real Xbox saves/autosaves and production asset I/O; measure CPU/GPU/memory/I/O independently.
- Co-op synchronization, multiplayer HUD, animations and routine mission skipping stay **deferred** until a functioning native Windows single-player game is independently verified.

No file from a commercial leak, unsupported third-party shader injector, GPL source merge, background service or new scheduled monitoring was used in this batch.
